<known_gaps>

Honest reading of what Slice A actually shipped (per codex audit):

- **Lex still cwd-driven.** `isBrainstormCwd()` in brainstorm-store.ts decides registration. lex-voice-ws.ts binds to "any non-exited PTY whose cwd ends in /brainstorm". Single-Lex assumption is still baked in. "First-class object" is true at the SQL row level but NOT at the runtime binding level. Fresh Claude must NOT assume multi-Lex or non-brainstorm cwd Lex works.
- **endBrainstorm() never auto-fires on PTY exit.** UI "end session" button calls ptyKill but does not PATCH the brainstorm row. Records leak as `status='active'` forever. Fix: hook pty.onExit in pty-host.ts to call `endBrainstorm()` for any pty that has a brainstorm row.
- **Slice A is schema + CRUD only.** `turn_count` never increments. `topic_tags_json` never updates. `derived_label` never derives. No "what should we call this brainstorm?" prompt flow yet. These are Slice A polish items, not done.
- **Slice C artifact parsing pipeline = NOT STARTED.** Only manual appendArtifact CRUD exists; no extraction of fenced JSON blocks from Lex's stdout, no auto-persist, no auto-reminder creation in notes mode.
- **System prompt still hardcodes environment facts** (RTX 4080, paths). Codex flagged this; Slice D explicitly rewrites prompt as policy + tool-call snapshots.
</known_gaps>
